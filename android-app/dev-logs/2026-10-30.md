## 1. Tasks & Changes Performed

1. **Targeted Fix 1: Coroutine Cancellation Preservation (`BackupManager.kt`):**
   - Caught and rethrown `kotlinx.coroutines.CancellationException` before generic `catch (e: Exception)` in both the inner image-extraction read loop and the outer staging/streaming block in `exportData()`.
   - Added `coroutineContext.ensureActive()` calls inside the transaction loop and image extraction try-block for responsive cooperative cancellation.
   - Ensured `finally` staging file cleanup and guaranteed release of `backupSyncMutex` via `withLock`.
   - Guaranteed `exportData()` never returns `ExportResult(success = false)` on cancellation; rethrows `CancellationException`.
   - In `importData()`, ensured `CancellationException` is rethrown across JSON reading, payload decoding, database transaction execution (cleaning up temporary image files), and promotion loops.
   - Updated test `export_cancellationPropagatesAndReleasesMutex` to assert that `CancellationException` propagates out of `exportData`, `exportResult` is null, `exportJob.isCancelled == true`, and `backupSyncMutex.isLocked == false`.
   - Added test `export_cancellationDuringImageRead_propagatesAndReleasesMutex` proving that cancellation raised during image reading propagates and releases the mutex rather than converting into a missing-attachment warning.

2. **Targeted Fix 2: Avoid Misleading Warnings for Deleted Transactions (`BackupManager.kt`):**
   - In `exportData()`, guarded missing internal receipt accounting with `if (!tx.isDeleted)` so missing image files for soft-deleted transactions are excluded from user-facing `missingImageTxIds`.
   - In `importData()`, identified `deletedTxIds` from incoming transactions and skipped soft-deleted transactions (`if (tx.isDeleted) continue`) during missing payload checks, payload decode error handlers, and promotion error handlers.
   - Preserved tombstones (`isDeleted = true`) and attachment metadata (`imageUri`, `imageFileId`) in both exported backup envelopes and Room database without clearing or rewriting.
   - Preserved `LinkedHashSet<String>` accounting to ensure each affected active transaction is reported at most once.
   - Added regression test `import_missingPayload_ignoresSoftDeletedTransactions_andPreservesMetadata` verifying active transaction missing payload is reported, deleted transaction is not, and both preserve metadata/tombstones in Room.
   - Added regression test `export_missingPayload_ignoresSoftDeletedTransactions_andPreservesMetadata` verifying active transaction is reported, deleted transaction is not, and exported JSON preserves both.

3. **Targeted Fix 3: Concurrency Test Renaming & Clarification (`BackupExportSafetyAndFeedbackTest.kt`):**
   - Renamed `export_noDeadlockFromNestedLockAcquisition` to `export_sequentialInvocationsAcquireAndReleaseMutexWithoutDeadlock`.
   - Clarified KDoc and inline documentation: test exercises sequential single-thread acquisition/release of the non-reentrant mutex without deadlocking; does not claim nested reentrancy or concurrent interleaving.
